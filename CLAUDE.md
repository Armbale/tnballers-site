# tnballers.com

Live site: https://tnballers.com (Netlify project "tnballers", publishes the `site/` folder on every push to `main`).

## Layout
- `site/index.html`: the published homepage. Generated by `src/tools/build_home.py` from `src/parts/home.html` + the data files. Never edit by hand.
- `site/about/index.html`, `site/privacy/index.html`, `site/terms/index.html`, `site/cookies/index.html`, `site/accessibility/index.html`, `site/scouted/index.html`, `site/submit/index.html`, `site/book/index.html`, `site/404.html`: standalone pages. Each has the same topbar / theme toggle / footer as the homepage and its own `<title>` and `<meta description>`. Generated by `src/tools/build_pages.py`. Never edit the output HTML by hand.
- `site/img/people/<slug>.jpg`: self-hosted photos for Canada's Best, sidelined, legends. Sourced from Wikimedia Commons under commercial-use licences (CC BY, CC BY-SA, CC0, PD). Credits in `site/img/people/CREDITS.md`. Never hotlink; download, resize to ~800 px, keep the file-page URL in the credits.
- `site/fonts/`: self-hosted Tanker (display) and Switzer (body) from Fontshare under FFL v2.0. Serve the shipped `.woff2` files as-is (subsetting and format conversion are banned by FFL §02). `LICENSE.txt` stays next to the files.
- `site/vendor/`: vendored GSAP + ScrollTrigger + Lenis (minified, with licence headers). No third-party CDN requests at runtime.
- `site/players/<key>.png`: partner-player transparent cut-outs. Used by the homepage and by Canva template fills.
- `site/social/<YYYY-MM-DD-slug>/`: Reel + Story + feed assets generated by `src/tools/social_formats.py`.
- `src/`: everything the site is built from.
  - `src/parts/home.html`: the homepage template. `build_home.py` substitutes the dynamic blocks (ticker, Canada scoreboard, sidelined, legends, metrics, `window.ninePlayers`, `window.peoplePhotos`, `window.canadaBest`, `window.sideList`, `window.feedPosts`, `STATS_ASOF`, live-7 count).
  - `src/parts/nine_data.js`: the 8 TNB partner players (stats per competition in `comps`, `STATS_ASOF` date at the top, highlights, sources, confirmed `ig` + `igHandle`).
  - `src/parts/feed.json`: the Live Tracker feed (newest items show on the homepage; all on the Canada tab). Add one item per real event: {"date":"YYYY-MM-DD","tag":"TNB|Goal|Trophy|Award|Injury|Transfer|Call-up|Matchday","headline":"short","detail":"one or two sentences with the facts","link":"source URL"}. Keep the newest ~30; drop older ones.
  - `src/parts/make_canada.py`: "Canada's best right now" (`BEST`), the sidelined list (`SIDE`), and the legends section (`NOW`, `HOME`, `MOMENTS`). Also update the "as of" date in the `can-note` text. Also `LEGEND_PHOTO` (legend name to photo slug for the homepage legends slider) and `WOMEN` / `WOMEN_ASOF` (the "Canada's women" section: club, caps, international goals, note; update after every CanWNT window and NSL matchday). `build_home.py` imports this as a module to read the data arrays (don't add import-time side effects outside the `if __name__ == '__main__':` block).
  - other `src/parts/*`: page sections, styles and scripts.
  - `src/tools/build_home.py`: renders `site/index.html` from `src/parts/home.html` + the data files.
  - `src/tools/build_pages.py`: generates the standalone pages (`/about/`, `/scouted/`, `/submit/`, `/book/`, `/privacy/`, `/terms/`, `/cookies/`, `/accessibility/`, `/404.html`).
  - `src/tools/fetch_people_photos.py`: pulls fresh Wikimedia photos for Canada's Best + sidelined + legends. Writes `site/img/people/*.jpg` + `CREDITS.md`.
  - `src/tools/test_cards.py`: Playwright headless check that opens each partner-player card modal.
- `src/build.sh`: rebuilds the whole site. Runs `build_home.py` then `build_pages.py` then prints `Built ../site/index.html`.

## Updating stats
1. Edit only the data in `src/parts/nine_data.js` and/or `src/parts/make_canada.py`.
2. Update `STATS_ASOF` in `nine_data.js` and the "caps as of" date in the `can-note` in `make_canada.py` to today's date, e.g. "18 Oct 2026". The homepage picks both up at build time.
3. Run `src/build.sh`. If it fails, fix or revert; never push a failed build.
4. Sanity checks before committing: season totals never go down; minutes <= 90 x apps (+ extra time); a player can't gain more goals than games played that day would allow. If a number looks wrong or can't be confirmed from two sources, leave the old value and say so in the report.
5. Commit `src/` and `site/` together with a message like "Stats update 18 Oct 2026: Olguin +1 app, ..." Netlify goes live about a minute after a push to `main`.

## Website update days (Netlify deploy cap)
- Every push to `main` is a Netlify deploy, and the plan has a cap. Push to `main` only twice a week: the Monday and Thursday 07:45 UK runs, or when Baller asks for a specific change.
- Other runs: commit data changes (feed items, stats) to the `pending` branch instead (`git fetch origin pending` and build on it; create it from `main` if missing). Never push `pending` into `main` outside an update day.
- Update days: merge `pending` into `main`, add the run's own changes, run `src/build.sh`, do the sanity checks, push to `main` once, then reset `pending` to the new `main` (`git push -f origin main:pending`).
- Reports on other runs say "queued for <next update day>" instead of "pushed".

## Rules
- Stats source: FotMob player pages (IDs are in the data files). Cross-check goals, injuries and transfers with a second source.
- Do not reveal individual market values or their sources.
- Keep Canadian/British spelling.
- No em dashes (—) anywhere user-facing: site copy, legal pages, feed items, Instagram captions, daily tracker. Use a full stop, a comma or a colon instead. En dashes (–) are fine for score lines and date ranges.
- No analytics, trackers, external scripts, cookies or third-party fonts. Everything self-hosted. CSP enforces this at the browser.
- No secrets, API keys, tokens or passwords in the repo (it's public).
- Netlify form field names are LOCKED byte-identical: `booking` (name, email, phone, who, service, date, location, budget, details, consent) and `recruit` (first-name, last-name, email, position, club, age-group, guardian-email, about, raw-footage, footage-link, consent) plus the honeypot `bot-field` and the hidden `form-name`. Never rename a field.
- Security headers live in `netlify.toml` (CSP, HSTS without preload, X-Frame-Options DENY, X-Content-Type-Options nosniff, Referrer-Policy, Permissions-Policy). Any new third-party domain or inline script needs the CSP updated to match.
- Run `/security-review` before every push to `main`.

## What makes a good TNB post (editorial rules)
- Canada first. Every post needs a Canadian subject, or the Canadian angle as the headline ("Davies' teammate Kane wins the Ballon d'Or", not "Who wins the Ballon d'Or?"). Pure global stories go nowhere: skip them.
- Timely. Only draft a post if its suggested publish time is within about 12 hours of the moment. Older news goes on the website feed only.
- Short captions: a hook of 10 words or fewer, 2–3 short lines of facts, the tnballers.com line, the 📸 credit, 6–10 hashtags. Ask a question only when people have an easy, obvious answer.
- Times: Toronto evening (roughly 17:00–21:00 Toronto) unless Metricool's best-time data says otherwise.
- Canadian MLS clubs (Toronto FC, Vancouver Whitecaps, CF Montréal): every result gets a full-time post (Matchday template, "🍁 FULL TIME", score as the headline), win, draw or loss, published straight away (see Metricool) as long as it's within the 12-hour window. If there's no usable real photo, use the TNB crest in the photo slot (fitted, not cropped) and "📸 TNB graphic" in the caption.
